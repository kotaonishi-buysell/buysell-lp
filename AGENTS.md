# Repository instructions

## Read before frontend work
- Read README.md and docs/design/README.md to identify the target LP.
- For /downsizing, read docs/design/downsizing/DESIGN_SYSTEM.md.
- For /home-value, read docs/design/home-value/DESIGN_SYSTEM.md.
- For changes affecting multiple LPs, read each affected LP's design system.
- For home-value, also read src/content/lps/home-value/README.md.
- For home-value business requirements and behavior, read docs/requirements/home-value.en.md. Its confirmed facts and seven-section sequence supersede earlier draft copy.
- For /silver, read docs/design/silver/DESIGN_SYSTEM.md. Silver loads silver.css only through SilverLayout; never import silver.css or base.css into the other LPs.
- For /gold, read docs/design/gold/DESIGN_SYSTEM.md. Gold loads gold.css only through GoldLayout; never import gold.css, silver.css or base.css into another LP.
- For /gold-v2, read docs/design/gold-v2/DESIGN_SYSTEM.md. Gold v2 loads gold-v2.css only through GoldV2Layout; never import it, gold.css, silver.css or base.css into another LP.
- For /appraisal, read docs/design/appraisal/DESIGN_SYSTEM.md. Appraisal loads appraisal.css only through AppraisalLayout; never import appraisal.css into another LP. It shares src/scripts/silver.ts with Silver, so check both when you change that script.
- For /replace-pwshp, read docs/design/replace-pwshp/DESIGN_SYSTEM.md and docs/lp-house-call-spec.md. It loads replace-pwshp.css only through ReplacePwshpLayout; never import replace-pwshp.css into another LP. It shares src/scripts/silver.ts with Silver and Appraisal, so check all three when you change that script.
- Preserve the existing Astro application. Published: /silver, /gold, /gold-v2, /appraisal, /replace-pwshp, /downsizing (src/pages/[slug].astro, built from the LP registry src/content/lps/index.ts), /home-value, /sms (the text-message sign-up page: legal layout, no LP stylesheet, no analytics; docs/forms/sms-verification.md) and the legal pages. There are no drafts now (/downsizing and /home-value were published on 2026-11-19). A draft is a page in src/draft-pages/ (Astro does not build that folder) listed in `draftRoutes` in astro.config.mjs: it is a route only in `astro dev` or with `npm run build:drafts`, never in the production build. To publish a draft, move its page into src/pages/ and remove its line from `draftRoutes`. / redirects to /silver (astro.config.mjs and netlify.toml).
- Apply Friendly Discovery styling only to home-value unless migration is explicitly requested.
- Keep legacy tokens.css, base.css and existing LP content unchanged for this addition.
- Reuse components where appropriate; keep page copy in src/content. All LPs share one contact form (src/components/ContactForm.astro, src/lib/contact-form.ts, src/content/contact-form.ts, docs/forms/contact-form.md). Change its fields, validation, delivery or endpoint in the shared files, and give each LP only a skin and its own panel, heading and button. The shared form has no analytics; each LP listens to its `cf:event` events. The service-area ZIP box is also shared (src/components/ZipCheck.astro; the ZIP prefixes live in site.serviceArea.zipPrefixes); it is not the contact form and sends nothing. Delivery has three modes set by env vars (see docs/forms/contact-form.md): our own function (default on Netlify: src/server/contact.ts, served by netlify/functions/contact.ts at /api/contact, which adds a row to a Google Sheet via src/server/sheets.ts (a service-account key) and/or emails the team; if it cannot take a request, the browser falls back to Netlify Forms, and the form markup carries data-netlify for that), Netlify Forms only (the browser posts to its own page), or preview. Host: Netlify, settings in netlify.toml; keep secrets in the Netlify dashboard, never in the repo. Home Value must not load the legacy analytics.
- Never introduce a nested repository, a second package manifest or a new framework for an LP.

## Design and content
- Each LP's own DESIGN_SYSTEM.md is its design source of truth; there is no universal visual design system.
- Do not apply one LP's colors, typography, imagery, radii or layout rules to another LP.
- Add docs/design/<slug>/DESIGN_SYSTEM.md and register it in docs/design/README.md for every new LP.
- Shared components and form/analytics code may be reused. Scope visual changes to the target LP; verify both LPs if shared CSS or markup changes.
- Scope new CSS to body[data-lp="home-value"] in src/styles/home-value.css.
- Company facts shared by every LP (brand, registered name, group name, address, reception phone, hours, OCCC registration number and notice) live only in src/content/company.ts. Never type them into an LP's content or page. src/content/site.ts (Downsizing, Silver) and src/content/lps/home-value/config.ts derive from it. Keep the other legacy facts in site.ts and Home Value's own configuration in config.ts.
- Do not invent fees, service areas, accepted items, phone numbers or customer testimonials. A company fact that is null in company.ts shows as a {{TODO}} placeholder only on a draft page; every published page must omit it or use an explicit preview state, never a visible TODO or a dummy value. Never claim a registration we do not hold: while the OCCC registration number is null, no page prints a registration line or says we are registered.
- Purchase rule, the same on every LP (src/content/purchase-flow.ts): the visit is an appraisal only. We tell the customer the appraised amount at the visit and buy nothing at the customer's home (Texas Occupations Code 1956.067: a purchase at a temporary location may need a notice before each visit). If the customer decides to sell, we collect the items the next day, or the customer sends them to us. Payment is by bank transfer, and no payment time is promised. Never write "appraise and buy", "offer on the spot", "paid next day" or any same-day or next-day payment claim (tests/purchase-flow.test.mjs). Never say we take no photos or share nothing: Texas dealer rules require ID and item records.
- Privacy Policy, Terms and Do Not Sell or Share are one set of pages for every LP (src/content/legal.ts; docs/design/legal/DESIGN_SYSTEM.md). Link to them through site.links; do not write a separate policy per LP. Keep their text true to what the code does (data collected, no sale/sharing, analytics); if a change adds a tracker, a vendor or a new use of personal data, update legal.ts in the same change. They load no LP stylesheet and no analytics. The Google Tag Manager container (GTM-PQQFZ723: Google Ads, Meta Pixel, Google Analytics, Microsoft Clarity) is listed in docs/design/legal/GTM_CONTAINER.md; any tag change updates legal.ts in the same change. GTM is not loaded for visitors who opted out or send Global Privacy Control (src/lib/privacy-choice.ts).
- Brand and company, the same on every LP: the brand is REWORTH and its logo is public/images/brand/ (use src/components/BrandLogo.astro, dark logo on light backgrounds, light logo on dark ones); the company is BuySell America, Inc. Both come from src/content/company.ts. Do not type the brand or the logo path in an LP, and do not use "BuySell" as the brand; it stays only in company and group names (BuySell America, Inc.; BuySell Technologies). tests/brand.test.mjs checks this.
- Mark unconfirmed business facts using the existing {{TODO: ...}} convention, with one rule: a published page (src/pages/) never shows a TODO. There, leave the fact out, or word the sentence so that it promises nothing, and keep the open question as a `// TODO:` comment beside it (`npm run todos` lists it). A section that waits for legal review (Silver's and Gold's comparison, the customer testimonials) or for answers from the business (Downsizing's categories and resale FAQ, docs/requirements/downsizing-open-questions.md) is hidden behind its flag in src/content/lps/ until it is approved or answered.
- Consultation examples are hypothetical situations, not reviews.
- Use owned/licensed assets; do not copy Pestie assets or layouts.
- Keep mobile layouts, keyboard access, visible focus and readable contrast.

## Verify
- Run npm run check, npm run build and npm run todos. Then run npm run check:public: it fails if a published page prints a TODO (Netlify runs it after every build).
- Run npm test for changes to the contact form, its validation or delivery behavior.
- Confirm /silver, /gold, /gold-v2, /appraisal, /downsizing, /home-value, /sms, the legal pages and 404 are generated and / redirects to /silver. When there are drafts, run `npm run build:drafts` to confirm they still build.
- With no receiving endpoint configured (the default), the shared form validates locally, sends nothing, and must never report live receipt or emit a submit measurement event.
- After changing the shared form, verify /silver, /gold, /appraisal, /downsizing and /home-value in the browser.
- Do not deploy or merge as part of scaffolding.
